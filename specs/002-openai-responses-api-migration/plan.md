# Implementation Plan: OpenAI Responses API Migration

**Branch**: `002-openai-responses-api-migration` | **Date**: 2026-10-06 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/002-openai-responses-api-migration/spec.md`

## Summary

Migrate the CV/ATS Analyzer (`/api/cv/ats`) and CV Parser (`/api/onboarding/parse-cv`) from a Qwen-compatible serverless OpenAI endpoint to the official OpenAI Responses API using `gpt-6.1-sol` with low reasoning effort. PDFs are uploaded directly to OpenAI via the Files API and referenced in the Responses API call, eliminating the `pdf-parse` local extraction step. The frontend, database schema, and response contracts remain unchanged.

## Technical Context

**Language/Version**: TypeScript (Next.js 14+ App Router)

**Primary Dependencies**:
- `openai` npm package (v4+) — Responses API and Files API
- `@prisma/client` — Database persistence (unchanged)
- `@supabase/supabase-js` — Authentication (unchanged)
- ~~`pdf-parse`~~ — **REMOVED**

**Storage**: Supabase PostgreSQL via Prisma ORM (schema unchanged)

**Testing**: Manual end-to-end validation via quickstart scenarios

**Target Platform**: Vercel / Next.js serverless (Node.js 18+)

**Project Type**: Web application (Next.js full-stack)

**Performance Goals**: ATS analysis response within current Qwen endpoint latency bounds. Low reasoning effort selected specifically to optimize speed.

**Constraints**:
- API key (`OPENAI_API_KEY`) stays server-side only
- File validation (type, size ≤ 5MB) MUST happen before any OpenAI API call
- Response JSON shape MUST be byte-for-byte compatible with current frontend consumers
- No frontend changes permitted unless forced by a backend structural requirement

**Scale/Scope**: 2 backend route files, 1 lib file. Single-file refactor per route.

## Architecture Decisions (from research.md)

| Decision | Choice | Rationale |
|----------|--------|-----------|
| PDF delivery to OpenAI | Files API upload → `input_file` reference | Native Responses API file support; avoids large base64 payloads |
| Model | `gpt-6.1-sol` | Per spec requirement |
| Reasoning effort | `low` | Speed and cost optimization for structured extraction tasks |
| Prompting Strategy | Evidence-based, zero job-assumption | Identifies primary specialization first; suggests keyword opportunities only with existing resume evidence; 5-category 100pt breakdown |
| Truncation Elimination | Removed arbitrary 3k/4k limits | OpenAI 128k context eliminates need for slicing text mid-word/sentence |
| `parsedTextSnippet` | Return `""` | No local extraction; field is debug-only, not rendered in main UI |
| `parsedText` DB field | Store `""` for new uploads | Avoids extra extraction step; full context preserved when available |
| lib/openai.ts cleanup | Remove `LLM_BASE_URL`, `LLM_MODEL_ID`, `getTargetModel()`, Qwen fallback | Clean official client with build-time fallback |
| Error format | Preserve existing `{ error: string }` with status 500 | Frontend error handling unchanged |

## API Contracts

### POST /api/cv/ats

**Request** (multipart/form-data):
```
file: <PDF binary, ≤5MB>
```
**Request** (application/json):
```json
{ "resumeId": "<string>" }
```

**Response** (200):
```json
{
  "reportId": "<string>",
  "resumeId": "<string|null>",
  "fileName": "<string>",
  "score": 82,
  "detectedRole": "Game Developer / VR Engineer",
  "scoreBreakdown": {
    "parseability": 22,
    "experienceContent": 21,
    "skillsKeywords": 20,
    "structureCompleteness": 11,
    "recruiterReadability": 8
  },
  "strengths": [
    "Clear chronological career progression",
    "Strong technical achievements in real-time VR simulations"
  ],
  "metrics": {
    "missingKeywordsCount": 2,
    "formattingIssuesCount": 1,
    "redFlagsCount": 0
  },
  "keywordOpportunities": ["REST API", "State Synchronization"],
  "missingKeywords": ["REST API", "State Synchronization"],
  "actionableFixes": [
    {
      "type": "KEYWORD",
      "severity": "LOW",
      "issue": "REST API terminology not explicitly highlighted",
      "evidence": "Candidate describes building HTTP backend integrations in multiplayer module",
      "recommendation": "If accurate, explicitly state 'REST API' to improve search discovery."
    }
  ]
}
```

**Error responses** (400/401/500): `{ "error": "<message>" }`
